# Cards Under Glass

Read `docs/PRODUCT_SPEC.md` and `docs/ARCHITECTURE.md` before changing behavior. This is a personal, local-first desktop hobby app. Implement only the requested milestone; do not advance hosting/deployment or synchronization work without a request.

- Electron main owns SQLite and filesystem access. Keep renderer Node integration off, context isolation and sandbox on. Expose narrow typed preload operations, validate IPC payloads and sender, deny navigation/windows/permissions. No backend, accounts or runtime network dependency.
- UUID and 10-digit human serial are permanent. Zero is reserved. Allocate atomically through `serial_reservations`, retain tombstones after card deletion, enforce uniqueness and immutability in SQLite, retain historical ranges, and never renumber or reuse. Changing ranges affects future cards only.
- All metadata is optional. Persist blank text as null; fallback labels are display-only. Submitted by is free text and must NEVER enter future public output. No tags or person directory.
- Preserve the unified card autosave ordering, error recovery and close/navigation flush protection. Never discard unsaved edits silently. Standard OS commands such as Command+Q are required and use the protected close path. Use explicit deliberate buttons for grading workflow actions; no custom workflow shortcuts.
- Keep Card Library preview selection and the active Card Grading card as separate renderer state. A Library row click changes only the read-only preview; only explicit **Open card** (or deliberate New Card creation) installs a grading editor. Preserve Library selection/scroll and the active grading card/tab/per-tab scroll across in-app workspace navigation. Do not silently restore an active grading card across full restart unless a later design adds safely library-scoped persistence.
- Store the Centering, Corners, Edges, Surface, and Estimated grades as integer tenths and centering measurements as integer hundredths of millimeters. There is no Defects grade. The single general Centering note belongs to the Centering grade. Required grade/measurement changes increment `assessmentRevision`; notes, defect markers, metadata and `includePublic` do not invalidate finalization. Finalized cards remain editable and show changes pending until finalized again.
- Card-owned records use foreign keys with `ON DELETE CASCADE`. Card deletion requires visible permanent-action confirmation; the serial reservation itself must never cascade or be deleted.
- Photos are card-owned. Keep originals unchanged under `media/originals/<card UUID>`, generated JPEG thumbnails under `cache/thumbnails/<card UUID>`, and only relative application-owned paths in SQLite. A primary slot has at most one photo; Additional Photos alone have editable titles. Photo locks block photo replacement/removal only and never block card deletion.
- An Additional Photo displays its custom title when present, otherwise its original filename; never store a fallback title. Rename is an explicit temporary edit with Save/Cancel. Blank Save clears the custom title without renaming or moving the stored file, and locks do not disable Rename.
- Keep image import, thumbnail generation and media resolution in main. Renderer drag/drop must pass `File` objects through preload `webUtils.getPathForFile`; never expose source paths or arbitrary filesystem access. The `cug-media` protocol accepts only a photo UUID plus `thumbnail`/`original` and resolves the corresponding active-library database row in main.
- Every native card-photo picker shares one machine-local `lastPhotoImportDirectory` in Electron user-data preferences. Supply it as `defaultPath` only while it resolves to a usable directory; remember the first selected file's parent only after a successful photo import. Cancelled/failed pickers and drag/drop never change it. Keep the absolute path out of SQLite, libraries, archives, public output, preload contracts and renderer state.
- Prepare and validate a copied original and thumbnail before committing a photo import/replacement. Commit the new row before best-effort cleanup of superseded files. Missing thumbnails may be regenerated from originals. Photo/title/lock/link changes do not alter grading revisions or finalization.
- Photo/defect links are same-card many-to-many records with database-enforced ownership and cascades on either side. Do not add defect taxonomy or per-photo publishing state.
- Keep defect/photo evidence navigable in both directions. The active Card Editor owns selected-marker and viewer-target state. Inspection linked-photo buttons open the shared full-resolution viewer without leaving Inspection; Photos marker buttons preserve Photos scroll, switch to Inspection, select the existing marker and scroll the Defect Map into view. Locks never block evidence viewing/navigation.
- Keep each photo's linked-marker disclosure state in the active Card Editor session alongside the other grading workspace UI state. Preserve every expanded photo disclosure across tab/workspace navigation, prune removed photo IDs, and do not persist this state to SQLite or across restart.
- Use ordered transactional migrations; never edit a migration already released. Reject newer schemas. Preserve originals; thumbnails and future public output are rebuildable.
- Manual Library Archive is a complete private replacement/recovery backup, never merge or synchronization. `.cug` is ordinary ZIP format version 1 with a `manifest.json`, a SQLite online-backup snapshot, every database-owned original, and SHA-256/size records. Exclude thumbnails and unrelated library files. Restore only into a separate new/empty folder, reject unsafe/undeclared/unsupported/corrupt contents before committing, extract to a same-parent staging folder, then rename into place. Preserve the library ID, originating installation UUID, allocation history and permanent serial reservations. Missing thumbnails regenerate lazily from restored originals.
- Public generation uses the explicit main-process allowlist and only current Finalized + Include-public cards. Never expose Submitted by, General Notes, internal UUIDs, or unlinked Additional Photos in public files/search/media. Keep serial report URLs and all asset links relative for root/subdirectory static hosting. Escape all user text and avoid `innerHTML`. Generate a Front-only 420-bound catalogue WebP plus 900-bound report preview and 2400-bound lightbox WebP derivatives from unchanged originals, all without enlargement.
- Treat `.cards-under-glass-site.json` as the sole generated-output ownership and incremental-generation record. **Update Public Site** is the normal path: deterministically fingerprint public-only card data and SHA-256 photo content, reuse current per-report HTML and image derivatives, repair missing owned files, and always refresh compact global files. **Rebuild Entire Site** bypasses reuse. Keep `REPORT_FORMAT_VERSION` and `IMAGE_PIPELINE_VERSION` explicit in `src/main/public-site.ts` and bump only the affected version when templates or image processing change. Never fingerprint or record Submitted by, General Notes, internal IDs, source paths, or unlinked Additional Photos. Stage changed output, replace/remove only previously owned safe relative files, preserve `.git`, `CNAME`, workflows and unknown content, reject conflicts/symlink traversal, and keep the prior generated site on failure. The output folder must remain outside the library. Site-output preferences are machine-local and keyed by library UUID. Never perform Git or hosting actions.
- Keep the public catalogue a responsive gallery headed **Card Reports**. Photo and placeholder tiles share one fixed 4:3 media region; ordinary catalogue images use only the dedicated lazy-loaded thumbnail. Use singular/plural report-count grammar. On report pages, preserve the formal serial heading and give Card Name its own strong secondary heading.
- Dark, restrained desktop UI. The default bounded catalogue query is permanent serial descending; edits must not reorder it by activity. Card Grading uses a compact two-row sticky identity/status/save/tab header without a legacy close action. Keep Full Card photos generous, while Corner and Edge preview surfaces stay in 2×2 grids with bounded responsive heights for laptop screens. Avoid enterprise dashboards and unnecessary frameworks.
- Packaging uses electron-builder with `package.json` as the one application-version source. Keep `package:mac`, `package:win`, `package:linux`, `package:all`, `package:clean`, and structural `package:validate` behavior accurate. Never reuse or present old `release` output as a current build. pnpm installs supported cross-platform Sharp binaries; the staged-package hook must retain only the target Sharp/libvips runtime, while `node:sqlite` remains Electron-bundled. A macOS cross-build proves package structure only; Windows/Linux runtime claims require their native CI/package tests.
- Update docs for new architectural decisions. Run `pnpm check`, `pnpm test:desktop`, the relevant package command, `pnpm test:packaged` on the host, and `pnpm test:development` for foundation/release changes. Do not claim checks that did not run.
